# Common Go authoring task and construction interfaces

Design a strong 9x9 Go policy by programming its neural weights. All weights
start at zero. No gradient descent, regression, fitting to examples, game-tree
search, rollouts, or neural forward passes during construction. No Internet,
GPU, Go engine, opponent weights, gameplay feedback or policy-output queries.
Use your Go knowledge and explicit formulas/circuits. Final evaluation samples
your policy against three held-out trained PPO opponents with no search.

## Game and network

Black first, board rows/columns 0..8. Capture connected opposing groups with no
orthogonal liberties. Occupied points, suicide and immediate simple-ko recapture
are illegal and masked. A move repeating an earlier whole-board position loses
for its mover; passes are exempt. Two consecutive passes or 162 moves end the
game. Area score counts stones plus empty territory surrounded only by that
color; White receives komi7.5. Output81 passes; output9*r+c places at (r,c).
Legal moves are sampled from softmax logits at temperature1, with no search.

Input has 243 binary values, index `(9*r+c)*3+p`: p0 own stone, p1 opposing
stone, p2 White-to-move (same flag at every point). Six hidden layers of width512
with ReLU, followed by 82 linear logits. Tensor names are W1,b1 through W7,b7:

- W1 [243,512], b1 [512].
- W2..W6 [512,512], b2..b6 [512].
- W7 [512,82], b7 [82].

`h1=relu(x@W1+b1)`; subsequent hidden layers use the same row-input/column-output
layout; `logits=h6@W7+b7`. Exactly 1,480,274 finite FP32 coefficients. Fixed
architecture; all coefficients editable. No extra inference wrapper or state.

## Interaction contract (same for both arms)

You have up to **eight response steps**, each allowing one construction program
or a final decision. Only weights persist between steps. Every response is
generated by a fresh Astra/xhigh invocation given this guide and the full visible
transcript of prior replies and construction feedback. Hidden reasoning state
is not resumed. This is a bounded construction experiment, not the original
120-run software allowance. Both interface descriptions are supplied to both arms.

Return a short design explanation and exactly one code fence tagged for SELECTED
ARM (`python` or `wspl`). Entire reply at most100,000 UTF-8 bytes. On later steps,
the current parent is your last accepted weights. A failed execution or invalid
candidate retains all previous weights and consumes that step. No automatic
repair or retry. You receive success/error diagnostics and shape/nonzero/min/max
statistics for every tensor; Python also returns bounded printed output. Nothing
evaluates the policy or reports game performance during construction.

When satisfied, reply with `FINAL` on the first line and a plain-text explanation,
without code fences. At the eighth response, the latest accepted weights are
automatically frozen whether or not you say FINAL. Returning FINAL immediately
keeps zeros. All sessions are retained and evaluated, including unchanged or
failed-to-improve ones. No gameplay-based checkpoint selection.

## Python/NumPy interface

Full Python3.12 and NumPy1.26.4 in an isolated sandbox. Helpers are provided:
`SHAPES`, `NAMES`, `np`, `load(name)` (copy of the current FP32 tensor),
`save(name,array)` (validate shape, cast to finite FP32 and update), `saved()`
(nonzero counts), `inp(r,c,p)`, `mv(r,c)` and `PASS=81`.
Use names W1,b1,...W7,b7. Every unsaved tensor retains its previous value.
Save all intended changes through `save`; after successful script termination
the harness exports the tensors. `load` returns copies: editing one without
calling `save` has no effect. An exception rejects the entire transaction.

Use formulas, loops, symmetry, NumPy indexing or linear algebra on coefficients.
Do not fit to data or compute the neural network's output/activations. You may
reason about Go rules without search, simulation or the neural forward pass.
Available software is Python standard library and NumPy; this is not the
original larger SciPy/sklearn/Torch sandbox. No child processes or host files.
Only accepted weights persist; scratch files do not. Stdout first20,000 bytes,
stderr last8,000 bytes returned. 120 CPU seconds/150 wall seconds,8GiB address
space,64MiB scratch tmpfs,8MiB output file. One execution per response.

## WSPL interface

Supply a complete WSPL0.2 program with this binding to current weights. The
harness substitutes the actual current artifact identity for the literal token:

```
wspl 0.2;
target base=artifact("parent",sha256="{{PARENT_SHA256}}");
edit base as candidate mode=fixed numeric=exact_to_storage {
  // your construction
}
```

Unwritten entries stay unchanged. `parent.W1[...]` etc read immutable current
parent weights; W1[...] reads current statement-start storage. Assignment and
`+=`, `-=`, `*=`; exact scalar/array `+ - * / @`, broadcasting, lists, slices,
`copy`, `reshape`, `transpose`, `zeros`, `full`, `eye`, `f32bits`. Each write
rounds directly to FP32 nearest/even. Python may round intermediate arithmetic
differently; the final fixed FP32 network is the common deployed object.

Declare `const gain=1/4;` before edit. Loops inside edit:
`for j in range(512) { W2[j,j]=1; }`. range(start,stop,step) is also supported;
all loops are construction-time only. Explicit indexing for every tensor axis.
There is no modulo, floor division, conditional statement, string-generated
tensor name, NumPy advanced indexing or hidden allocator. Split ranges and
explicitly name layers when necessary. Maximum100,000 expanded statements and
100,000 loop iterations,100,000,000 charged construction operations and1,480,274
stored elements. Wall limit160s including import/serialization. No graph growth.

Named circuits and explicit placement are available. Syntax-only example:

```
circuit Difference(a:Real,b:Real)->(u:Real) {
  p=relu(a-b); n=relu(b-a); u=p-n;
}
```

Place inside edit with
`place Difference(a=h5[0],b=h5[1]) at {p=h6[0];n=h6[1];u=y[0];} writes=replace_producers;`.
Bind every input and place every assigned local/output exactly once. Circuit
signals must cross adjacent layers; affine expressions use previous-layer
signals. ReLU producers occupy ReLU layers, linear producers the final linear
layer. Placement replaces the entire incoming column and bias of each producer;
two placements cannot reserve the same producer. Hidden layers are h1..h6;
inputs x; outputs y. Raw edits can construct the same circuits and are equally
valid. No automatic concept discovery or verification of your strategic claims.

Coefficient-slice work is charged by selected size/rank rather than full tensor
size. Error diagnostics, plan resource counts and placement counts are returned,
along with the same per-tensor statistics as Python. This interface has bounded
construction semantics instead of executing arbitrary code; the two runtimes
are not compute-matched. Evaluation remains identical.
